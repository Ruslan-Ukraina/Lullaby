# lby-derpy-fixes

The small fixes of other people's code, in one place. Two parts:

**Fixes in Wine (the engine), links in this folder.** The patches stay in the series `patches/engine/patches/<module>/` (the bridge build
reads them there, in order of their numbers); the links here are named like the patches:
- ENG-01 `0001-ntdll-commit-charge-is-the-footprint.patch`: `PagefileUsage` is the physical footprint (games compare it with memory);
- ENG-02 `0001-win32u-d3dkmt-hardware-gpu-scheduling.patch`: hardware GPU scheduling reported on (Streamline offers frame generation);
- ENG-03 `0001-winemac-retina-horzres-not-doubled.patch`: `HORZRES`/`VERTRES` are not doubled on Retina;
- ENG-10 `0005-winemac-winemetalgl-client-view.patch`: WineMetalGL gets the engine's own metal view (the window follows moves, the title bar is opaque);
- ENG-11 and ENG-14 `0001-winecoreaudio-follow-default-devices.patch`: a render stream on the default output device and a capture stream on the default input device move with them (headphones or a headset in and out);
- ENG-04 and ENG-05 `0002-ntdll-d3dmetal-4b3.patch` and ENG-06 `0002-winemac-d3dmetal-find-best-window.patch`: the adaptation to D3DMetal 4.0 beta 3 (the dispatch table layout and the window search; only for that toolkit).
Not here: the V-Sync and present feed (ENG-07), GCMouse (`lby-octavia-gcmouse`), native full screen (`lby-trixie-fullscreen`).

**Fixes in WineMetalGL (OpenGL on Metal, CMP-10), the injected library `glfixes.m` -> `lullaby-glfixes.dylib`.** Injected into the Wine
loader's process (`DYLD_INSERT_LIBRARIES`, set by `compat_run.sh`); does nothing unless the process runs WineMetalGL (`WINEDLLOVERRIDES`
names `winemetalgl`). Names only (a symbol, a label), no offsets; arm64 and x86_64. Registry IDs GLF-02, MTL-01, MTL-02 and MTL-03. (GLF-01, 32 colour bits, is gone: WineMetalGL 3.9.0 lists 32 itself.)
- **GLF-02, a black window texture.** The colour texture of a window (label `default framebuffer`, private storage) is never cleared,
  at the start and when the window changes size; a game that swaps before it has drawn (a loading screen) showed the GPU's old memory,
  a flat magenta rectangle at the switch to native full screen. `MTLTexture setLabel:` is taken, and a texture given that label is
  cleared to black at once (waited for, before WineMetalGL copies the old picture into it). Switch: `LULLABY_GL_CLEAR=0`. Report:
  `agent/reports/winemetalgl-issue-draft-resize-uninitialised.md` (private).
- **MTL-01, a mesh pipeline without a fragment function.** Metal aborts the process ("Mesh Render Pipeline Descriptor Validation, fragmentFunction must not be nil") when a mesh render pipeline has a colour attachment and no fragment function. DXMT builds one for a Direct3D 11 pass with tessellation, a render target and no pixel shader (Modern Warfare Remastered after a mission loads). In Direct3D 11 that means no colour is written, so the library gives the pipeline an empty fragment function and a colour write mask of none, in the device's `newRenderPipelineStateWithMeshDescriptor:` and the binary archive's `addMeshRenderPipelineFunctionsWithDescriptor:`. For every Wine loader process, not tied to a game or to WineMetalGL. Switch: `LULLABY_MESH_FS=0`. Report draft to DXMT: `agent/reports/dxmt-issue-draft-mwr-mesh-pipeline.md` (private).
- **MTL-02, a tessellation mesh too large for Metal.** DXMT picks the largest tessellation factor (1..64) whose mesh `dxmt::dxbc::estimate_mesh_size` (exported by the engine's `winemetal.so`) puts at 32768 bytes or less, and the estimate is short: it rounds the strip's vertex count down to a multiple of 4 where Metal rounds up, and leaves the position out of a vertex. The pipeline at that factor is never made ("Failed to create tessellation raster PSO: Total mesh size (34560..36992) exceeds the maximum mesh size allowed (32768)", Modern Warfare Remastered in a mission, then a GPU reset). When `winemetal.so` is added, the function is found by name in its symbol table, checked byte for byte against DXMT v0.80 (the field's offset is read out of its own instruction, nothing fixed), and replaced with the same sum with the factor one more (the shader rounds a fractional factor up to even or odd: 57 gave 124 vertices, 33728 bytes, under the first version), vertices rounded up and two float4 more a vertex (one is the position, one is slack for a vertex with one more output than the field counts). The factor then drops a little (about 7-9 steps of 64 in that game). Another build of the function is left alone and named in the log. x86_64 only (the engine's `winemetal.so` is x86_64). Switch: `LULLABY_TESS_FIT=0`.
- **MTL-03, the group count of an indirect tessellation or geometry-shader draw.** Such a draw becomes a mesh draw whose group count DXMT writes on the GPU: every one in a render pass adds a task, and at the end of the pass one vertex shader of DXMT's own library (`ts_draw_arguments_marshal`, `gs_draw_arguments_marshal`) is meant to go over all tasks. In v0.80 its loop has no increment (upstream mended it after v0.80, `aadf0fb`, with zero and overflowing draws in `46911d7`), and the shader the engine ships does the first task only (its compiled code, read with `metal-objdump`, has no loop left), so the 2nd..nth draw of a pass takes its group count from a GPU buffer that is never cleared: whatever was there before, up to a billion groups. When those two functions are asked for by name, the library gives fixed ones built from source instead: every task, the loop bounded, a draw with no vertices, an incomplete patch or no instances and a count over the limit get 0 groups (the product in 64 bits: DXMT's 32-bit one let 2^31 groups x 2 through as 0). Only when Metal's reflection of DXMT's function shows v0.80's task layout (buffer 0, 32 bytes, field by field); another layout is left alone and named in the log. Not tied to one game; found in Modern Warfare Remastered's hang in a mission (display stuck, GPU restart). Test: `tests/marshal_test.m` (a stand-in that does what the shipped shader does; with a path, the engine's own library cut out of DXMT's `d3d11.dll`). Switch: `LULLABY_INDIRECT_ARGS=0`.
- GLF-02 goes when WineMetalGL mends it; MTL-01, MTL-02 and MTL-03 when DXMT does: `release/check-components.py` shows a newer WineMetalGL; read its notes, then remove what no
  longer applies.
- Tests: `make glfixes-tests` (a Metal texture, in a program named like the Wine loader; on, off and "not
  WineMetalGL"; arm64 and x86_64).
