# DXMT из закреплённого коммита `main` (Этап 7)

Дата: 2026-10-18. Статус: workflow написан, ещё не запускался; замеров нет.

## Что проверено

- `3Shain/dxmt`, `main` = `50102f994b406f58f56d5d09f2ad20f9b90390a2` (2026-10-16), 267 коммитов после `v0.80`. Это закрепляемый коммит (pin); менять только отдельным коммитом с причиной.
- Сборка DXMT — по их `ci.yml`: Wine-тулчейн `v8.16-3shain` (для `winemetal.so`), свой LLVM 15.0.7 для Darwin x86_64 (долго, кэшируется), mingw-w64, meson 1.10.0. Одна машина этого не соберёт без установки системных инструментов, поэтому сборка в CI (`.github/workflows/dxmt-build.yml`, запуск вручную).
- Что собираем: как в их релизной упаковке — x86_64 (gcc, release, `nvapi`+`nvngx`) и x86 (win32). **D3D12 выключен** (`enable_d3d12=false`): в `main` он ещё в основном заглушки, нам нужна проверка D3D11 без сюрпризов. ARM64EC не собираем (FEX/ARM64 не делаем).
- Dormison берёт DXMT готовым файлами (`package-engine.sh`, «donor»): `winemetal.dll`+`winemetal.so` — пара, менять только вместе. v0.80 с Wine 11.16 Dormison работает при `winemetal.so`, собранном против заголовков Wine 8.16, значит тот же рецепт для `main` должен подходить; **проверяется запуском**, не принимается на веру.
- В DXMT есть `AGENTS.md`: код для вкладов в проект нельзя генерировать ИИ. Мы ничего не отправляем им, только собираем их исходники; вкладов в апстрим от нас не будет.

## Как подменяется (после сборки)

Не перезаписью файлов движка: папка `renderers/dxmt-<pin>/` рядом с движком, как у прежнего плана для сторонних рендереров (`WINEDLLPATH_PREPEND`, раскладка `x86_64-windows`, `x86_64-unix`, `i386-windows`), выбор — настройкой рендерера на игру. `v0.80` из тарбола остаётся запасным и по умолчанию.

## Приёмка (по STACK_PLAN Э7)

1. Артефакт сборки: `SHA256SUMS` и `PIN` внутри; хеши заносим в манифест компонентов (BACKLOG п. 14).
2. Стенд: `perf/gfxbench.sh --renderer dxmt` против `v0.80` на трёх играх; ≥ 7 кругов, различия меньше ±4 % неразличимы, критерий тишины `--wait-quiet 75`. **Запуск игр — только когда ты отошёл, и я предупрежу.**
3. Регрессии D3D11: PEAK, Deadlock до меню (VAC-игры не запускаем), ещё одна DX11-игра.
4. Нет регрессии по FPS и стабильности — pin принимается; иначе остаёмся на `v0.80`.
