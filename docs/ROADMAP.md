1. Все адреса публикации — **одна конфигурация**, а не константы в коде: `bridge-manifest`, `signatures-manifest`, Sparkle appcast, артефакты движка/моста/сигнатур. По умолчанию — текущий публичный репозиторий.

   - публично (как сейчас);

   - при открытии проекта — открыть исходники вместе с артефактами.

## 4. Каталог настроек игры — единый источник для 7A и 8

**Принцип:** один каталог в коде (как `Core/SettingCatalog.swift` в Sevoflurane). Каждая настройка описана один раз: id, группа, уровни (для всех игр / для игры), значения, носитель (env-переменная, реестр, payload рендерера), значение по умолчанию, тексты (заголовок, строка-подпись, подсказка (i)) на трёх языках. Панель в Steam, окно «Дополнительные» и тесты рисуются из каталога. Ни одна панель не знает имён ключей сама.

**Хранилище — файлы движка:** `<prefix>/.sevo/bottle.env` («для всех игр»), затем `<prefix>/.sevo/apps/<exe>.env` (игра; `<exe>` в нижнем регистре). Плюс реестр — для настроек, которые Dormison читает из реестра. Формат строк и семантику «наследовать» сделай **совместимыми с Sevoflurane** (`Core/ConfigMaterializer.swift`):
- у игры строка пишется только для заданных ею значений;
- переключатель, отличный от значения «для всех игр», пишется явно `=0` или `=1`, а не пропускается;
- `SEVO_CPU_COUNT=0` значит «все ядра», это явное значение.

**Игра = appid, у игры может быть несколько exe** (у Deadlock: `deadlock.exe`, `vconsole2.exe`). Настройки хранятся по appid и материализуются в env-файл каждого известного exe. Список exe пополняется по факту запусков (`compat_run.sh` знает exe). До первого запуска — честная пометка «применится при первом запуске».

**Миграция:** текущие ключи NotProton (`NOTPROTON_RENDERER`, `NOTPROTON_RETINA` и др.) перевести в каталог без потери значений пользователя. `NOTPROTON_*` оставить только там, где движок сам ключ не читает (например, выбор рендерера в `compat_run.sh`). Устаревшие параметры запуска (`CX_GRAPHICS_BACKEND`, `WINEMSYNC=1`) — автоочистка, это уже есть в бэклоге.

## 5. Фаза 7A — все настройки игры в Steam

**Цель:** пользователь настраивает игру там же, где на Linux выбирает Proton, — в Steam. Окно NotProton для этого больше не нужно.

### 5.1 Свойства игры → Совместимость (через существующий webpatch)
- Верх — как в Steam Play на Linux: флажок «Принудительно использовать особый инструмент совместимости Steam Play» и выбор **Dormison (NotProton)**. Выбора движка Wine нет.
- Ниже — блок NotProton из **5 быстрых настроек**. Предварительный состав:
  1. Рендерер;
  2. Высокое разрешение (Retina);
  3. Апскейлер;
  4. Счётчик FPS;
  5. Ограничение FPS.

  Окончательный состав (3–5 пунктов) утверждает пользователь на контрольной точке. Покажи ему макет и предложи альтернативу: «Изменяемые окна» вместо Retina.
- Каждая строка — родными контролами и стилями Steam (выпадающие списки и переключатели как в окне свойств), с пометкой наследования («По умолчанию: DXMT») и (i).
- Кнопка **«Дополнительные настройки…»** открывает **диалог в стиле Steam внутри Steam** (модальное окно webpatch, не окно NotProton). Внутри все остальные строки каталога §4 по группам: Картинка, Мышь, Производительность и совместимость, Клавиатура, Диагностика. Внизу — «Сбросить настройки игры».
- Изменения пишутся в каталог и материализуются в env-файлы и реестр сразу. Применяются при следующем запуске. Если игра запущена — строка «Применится после перезапуска игры».

### 5.2 Настройки Steam → Совместимость («для всех игр»)
- Как раздел Steam Play на Linux: значения по умолчанию для всех игр (уровень `bottle.env`) теми же контролами. Если в этом разделе Steam на macOS нет места для вставки — найди ближайшее родное место и опиши выбор в DECISIONS.

### 5.3 Меню View в игре
- Dormison вызывает `SEVO_CLI` для части пунктов меню View (апскейлер, FPS). Оцени маленький совместимый CLI NotProton, который принимает те же вызовы и пишет в наш каталог. Тогда выбор в игре сохраняется. Если дорого — пометь пункты как «только до выхода из игры» и запиши в BACKLOG.

### 5.4 Что убрать
- Окно «Настройки игры» в NotProton.app — после переноса в Steam. Окно NotProton целиком переделывается в Фазе 8.

### 5.5 Приёмка 7A
- Тесты: каталог ↔ строки env/реестра для каждой настройки, включая «наследовать», явный `=0` и несколько exe на игру (как `ConfigSwitchTests`, `ConfigMaterializerTests` в Sevoflurane); фикстуры webpatch для панели и диалога; тест на полноту трёх локализаций.
- Ручная проверка (пользователь): PEAK — сменить рендерер, апскейлер MetalFX, счётчик, ограничение 60 FPS → всё действует в игре. Deadlock — настройка применяется к обоим exe. Сброс работает. Настройки «для всех игр» наследуются. Язык панели меняется с языком Steam.

## 6. Фаза 7B — D3DMetal (Apple Game Porting Toolkit), DX12

**Эталон:** Sevoflurane `Core/Setup/D3DMetalInstaller.swift`, `D3DMetalPatches.swift`, `Sevoflurane/Setup/GPTkDownload.swift`. Dormison уже поддерживает D3DMetal хоста GPTK 3.0 и 4.0, включая таблицу колбэков 4.0 (README Dormison).

- **Получение:** пользователь сам скачивает у Apple образ «Evaluation environment for Windows games» (или большой «Game Porting Toolkit», в нём тот же образ). Нужен бесплатный Apple ID, лицензию принимает он сам. В NotProton:
  - кнопка «Добавить Game Porting Toolkit…» (выбор .dmg или перетаскивание);
  - по желанию — встроенный вход Apple в `WKWebView`, как в Sevoflurane;
  - ничего не хостим и не распространяем.
- **Установка:** как требует Read Me Apple — `redist/lib/` поверх `lib/` движка, с сохранением раскладки Apple (`.so` — симлинки в `../../external/`). Несколько версий рядом: `d3dmetal/<версия>/` в общем хранилище, которое переживает обновления движка. По умолчанию — новейшая (бета, где работа над DX12). Учти, что EngineUpdater заменяет дерево движка: D3DMetal должен доставляться в новое дерево при каждом обновлении и откате.
- **Где живёт кнопка:** в Фазе 8 окно NotProton минимальное. Поэтому «Добавить GPTK» — в «Дополнительных настройках» в Steam, при выборе рендерера D3DMetal («D3DMetal не установлен — добавить…»), плюс пункт в шестерёнке NotProton.
- **macOS:** D3DMetal 4 требует macOS 27. На macOS 26 — честная пометка, доступен только GPTK 3, если он есть.
- **Рендерер D3DMetal** появляется в каталоге и в панели Steam только после установки.
- **Исправления для игр** (по необходимости, на конкретных играх):
  - `tsshim/d3d12.c` из Highball (GPL-3.0): прокси перед d3d12 D3DMetal — временные метки, shader model, MSAA depth resolve;
  - байтовые патчи D3DMetal по SHA-256, как в `D3DMetalPatches.swift` Sevoflurane, с сохранением оригинала.
- **Цель-проверка:** RE9 (DX12, в Фазе 1 падал с «Unsupported graphics card») — до главного меню. Forza Horizon 6, если есть у пользователя: рецепт `highball-db/recipes/games/forza-horizon-6.json` (macOS 27, D3DMetal 4, GPU Intel Arc A750, msync, tsshim). Честно учти разницу: у Highball Windows-Steam в бутылке, у нас мост к Steam для Mac.
- **Приёмка:** тесты установщика (несколько версий, симлинки, переживание обновления и отката движка), ручная проверка RE9.

## 7. Фаза 7C — Mullion (эксперимент)

**Факты (README Mullion):**
- D3D10/11/12 на Metal поверх DXMT (форк DXMT от 16.09.2026);
- SM 6.0–6.6, DXR 1.1;
- требования: M3+, macOS 15+, x86_64 Wine, только 64-битные игры;
- LGPL-2.1+, pre-release;
- архив релиза в раскладке DXMT (`x86_64-windows`, `x86_64-unix`);
- его `install.sh` **заменяет** Direct3D Wine в `lib/wine` — **так не делать**, иначе ломается DXMT;
- сообщает AMD vendor ID, Apple — через `DXMT_CONFIG="dxgi.customVendorId=106b"`;
- сборка с `-Dwine_builtin_dll=false` даёт DLL для `system32` с `WINEDLLOVERRIDES="d3d12,d3d12core,d3d11,d3d10core,dxgi=n"`.

**План:**
- Mullion — отдельный payload рендерера: своя папка, тот же механизм выбора рендерера на игру, что для DXMT/DXVK. Файлы движка не перезаписывать.
- Версия и sha256 закреплены. Обновление — через наш подписанный манифест (семейство компонента `mullion`, схема Фазы 5/6).
- Показывать только при M3+ и macOS 15+, для 64-битных exe. Иначе строка скрыта или выключена с объяснением.
