Рендерер здесь не показан: по ROADMAP он только «на игру» (для всех — DXMT).
Как это устроено (коротко)
  1. Один каталог настроек в Swift: id, группа, уровни, значения, носитель, тексты en/uk/ru, подсказки (i). Панель в Steam и тесты рисуются из него — имён ключей панель не знает.
  2. Хранилище — по appid (notproton/settings/), «для всех игр» — отдельный файл. Сразу материализуется в каждый префикс: .sevo/bottle.env = «для всех игр», .sevo/apps/<exe>.env = только заданное игрой (явные =0/=1, SEVO_CPU_COUNT=0), как в Sevoflurane.
  3. Реестр (Retina, имитация разрешения, Command как Ctrl) — run-скрипт пишет при запуске, как Retina сейчас: у префикса без запущенной игры нет wineserver.
  4. Несколько exe: список пополняют run-скрипт и строки sevo:loader exe=… лога Wine; до первого запуска — пометка.
  5. Связь панели с файлами: маленький CLI notproton-settings (тот же Swift-код). Его же движок вызывает из меню View (SEVO_CLI) — выбор в игре сохраняется (§5.3).
  6. Канал «JS в Steam → CLI»: dylib в Steam Helper. Нужна одна живая проверка со Steam — только с твоего разрешения.
